The implemented Python SDK records application-provided observations; it stores normalized event records locally; the CLI inspects, validates, and summarizes traces. Examples shown on-screen are synthetic illustrations, not production metrics.

Data and implementation boundaries

Redaction is pattern-based best effort. The library makes no network calls itself. The browser dashboard, automatic framework adapters, hosted ingestion, and measured token-cost views remain roadmap items.

Read the full narration / scene notes

01 — The problem

AI agents do more than generate a final answer. They may call language models, invoke tools, retry operations, and fail between steps. Without a recorded history, the final answer alone cannot show how the run unfolded.

02 — Record the trace

AgentGlass lets application code record observable run lifecycle events, model request or response metadata, tool starts and completions, outputs, and failures. It records what the application explicitly supplies rather than automatically intercepting every provider.

03 — Normalize the evidence

Every trace event uses a versioned schema containing an event ID, run ID, sequence number, timezone-aware timestamp, type, status, and attributes. Optional parent links connect related start and terminal events. Invalid records are rejected by validation.

04 — Timing and relationships

Context managers time instrumented operations and connect completion events to their start events. This supports inspection of step durations and relationships. These are measured operation times, not performance benchmarks; cost and token data are not invented when provider usage is unavailable.

05 — Privacy before persistence

Before storage, the default redactor masks common secret-bearing keys, recognizable token patterns, and email addresses, and bounds payload sizes. No pattern-based system can guarantee detection of every secret. Avoid collecting sensitive data where possible and review exports before sharing.

06 — Local storage and CLI

AgentGlass supports an in-memory store for tests and a local append-only JSONL store. The CLI can generate an offline synthetic trace, inspect events, validate the file, and summarize counts per run. The demo makes no external model call.

07 — Shipped versus planned

The current repository includes the Python tracing core, event contract, local stores, redaction, CLI, tests, and CI. A live dashboard, tested framework adapters, provider-backed token and cost attribution, and hosted ingestion are future goals, not shipped capabilities.
